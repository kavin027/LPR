# Selector range and tie sensitivity protocol

Use the existing five-group-fold exact-set hit counts over the original 75 registry examples; keep every evaluation ID, candidate rule, fitted score component and coefficient unchanged. Use all 42 registries and both Spider evaluation cohorts for each Spider registry. Preserve the published order of the positive-inverse grid. For the new joint sensitivity append the six count-only settings (alpha = 0) in their original order; the first maximum therefore preserves hybrid on cross-family ties. Report count-first on any cross-family tie as a separate sensitivity. Query annotations play no role in either choice.

For each registry and search family record the number of co-winners, their metrics, and both the gap to the next *configuration* (zero for ties) and the gap to the next *distinct hit count*. Re-score every registration-tied maximizer with the previous decoder implementation and verify all selected arms against the released masks. The minimum and maximum evaluation performance among ties are descriptive, query-outcome-aware bounds and cannot be used for selection. Count ties across distinct hyperparameter configurations, including ones with identical query decisions. No training, power analysis or new cohort.
