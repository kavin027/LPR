# Rebuilt index, r88

Use Python 3 from this directory and run `python verify_index88.py`. The standard-library checker rebuilds the SQLite postings from the frozen record masks, executes all single-label and registered two-label lookups, compares each returned ID against the archived lists and checks the resulting per-lookup and macro summaries.

* `index_inputs.json.gz` holds the registered masks, label order, original request ID, gold cohort and the masks for gold, Base + Forward, ECP, Row, Spherical, soft mapping, Base + Forward + mapping and Full LPR, in that order. In the two unsupported SpiderOps records, gold preserves only the registered coordinates for these lookups. The strata are mutually exclusive. For each cohort, restrict returned and gold record IDs, retaining the identical registered predicates. Unsupported records occur only on SpiderOps.
* `lookups.csv` contains TP, FP, FN, TN, both-empty flags and F1 by lookup, arm and gold cohort. `summary.csv` reports equal-lookup mean F1 and pooled counts. The primary workload uses arity 2. Arity 1 is retained for replay continuity.
* `retrieved_ids.json.gz` contains the complete returned and gold record-ID lists for every global lookup. Join `index_inputs.json.gz` on task and record ID to reconstruct a cohort partition.
* To regenerate the compact input from the original r87 compact replay, use pandas and NumPy with `python prepare.py PATH_TO_EXTRACTED_REPLAY`. It requires each task and ID to join one-to-one and checks that Base + Forward, direct mapping and Full reproduce independently archived predictions. `python verify_index88.py --write` regenerates the derived files.
* On the original primary CrossWOZ/SpiderOps registries, the pre-existing exact-set weights were ECP 1/.5, Row .25/.5, Spherical .25/.5, Base + Forward + mapping .5/1, and Full .25/.5. The direct-mapping-only predictions have no mixing weight. Gold is used for evaluation and for identifying the post-hoc record cohorts. Lookup selection uses only the original registry.
